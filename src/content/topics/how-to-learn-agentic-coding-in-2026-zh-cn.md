代理式编码（agentic coding）指的是把*任务*——而不是一次按键——交给 AI 智能体。你不再是接受自动补全的下一行，而是描述一个成果（"给这个 API 加上限流，并用测试覆盖"），智能体自己规划步骤、修改多个文件、跑测试、回报结果。这已是工程师的核心能力，而学得最快的人把它当成*工作流纪律*，不是工具小技巧。

## 智能体编码到底是什么

智能体编码工具跑的是一个循环：**规划 → 修改 → 验证 → 重复**。2026 年的主流工具：

- **Claude Code**（Anthropic）——终端原生的智能体，具备会话、以 CLAUDE.md 为载体的持久记忆、hooks、skills、子智能体（subagent），以及沙盒化的权限模型。
- **OpenAI Codex**——OpenAI 的编码智能体，CLI 与 IDE/云端皆可用，擅长规约驱动的长时任务。
- **OpenCode**——开源、模型无关的智能体：同样的循环，但底层模型由你选。
- IDE 内嵌智能体——用便利换深度的一型。

把智能体与自动补全区分开的是*验证*。好的智能体会读自己的 diff、跑测试套件、持续迭代。你的工作从敲代码转为**写规约、做审查、守门禁**。

## 真正有效的学习路线

### 1. 命令行与 Git 熟练度（第 1 周）

智能体活在终端里。如果 `git diff`、`git log`、分支、rebase 还不是肌肉记忆，先补这个——所有代理式工作流都建立在审查 diff 之上。

### 2. 深学一个工具（第 2〜4 周）

选 Claude Code 或 Codex，把它学*透*：会话管理、记忆文件（什么该进 CLAUDE.md、什么不该）、权限模式、hooks、自定义命令。扫过教程你得到的只是一个聊天机器人；吃透配置面，它才会变成交付机器。

- 选 Claude Code：[Claude Code 从入门到项目实践](/zh-cn/books/claude-code/)——从第一条命令讲到 hooks、skills、子智能体、沙盒与 MCP，最后以两个真实项目收尾。
- 选 Codex：[Codex 从入门到项目实践](/zh-cn/books/codex/)——从基础到 OpenAI 工具链上的生产级项目。
- 想懂工具背后的心智模型：[图解 AI Agent](/zh-cn/books/ai-agents/) 用可视化讲透规划、工具调用与记忆架构。

### 3. 在真实代码库上练（第 4〜8 周）

不是 todo 示例——是你真正在乎的代码库。先给智能体小而可验证的任务（"给这个端点加测试"），每个 diff 都审，审查能力跟得上才放大任务。最重要的纪律是：**解释不了的 diff 绝不合并**。

### 4. 扩展工作流（第 8 周起）

2026 与 2024 的分野在这里：规约驱动开发、智能体必须通过的 CI 门禁、把团队规范固化成自定义斜杠命令、用子智能体并行作业。上面两本旗舰书的后半部整段都在讲这件事——与智能体一起交付*完整项目*，而不只是改文件。

## 常见错误

- **Prompt 先行思维。** 智能体会放大清晰的规约，救不了含糊的规约。
- **跳过审查门。** 正因为是智能体写的，你更得读两遍。
- **收集工具癖。** 浅学六个不如深学两个。精通一个之后，模型无关的 [OpenCode](/zh-cn/books/opencode/) 是对冲。
- **没有验证循环。** 测试太弱，智能体编码只会让交付*更慢*，不会更快。

## 一句话总结

深学一个智能体、让人守住审查门、在真实仓库上练、用规约与 CI 扩展。想要书本形式的完整路线，[AI 与智能体开发系列](/zh-cn/series/ai-agents/)会带你从第一条命令走到交付的项目。
