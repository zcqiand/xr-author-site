代理式編碼（agentic coding）指的是把*任務*——而不是一次按鍵——交給 AI 代理。你不再是接受自動補全的下一行，而是描述一個成果（「幫這個 API 加上限流，並用測試覆蓋」），代理自己規劃步驟、修改多個檔案、跑測試、回報結果。這已是工程師的核心能力，而學得最快的人把它當成*工作流紀律*，不是工具小技巧。

## 代理式編碼到底是什麼

代理式編碼工具跑的是一個迴圈：**規劃 → 修改 → 驗證 → 重複**。2026 年的主流工具：

- **Claude Code**（Anthropic）——終端原生的代理，具備會話、以 CLAUDE.md 為載體的持久記憶、hooks、skills、子代理（subagent），以及沙盒化的權限模型。
- **OpenAI Codex**——OpenAI 的編碼代理，CLI 與 IDE/雲端皆可用，擅長規約驅動的長時任務。
- **OpenCode**——開源、模型無關的代理：同樣的迴圈，但底層模型由你選。
- IDE 內嵌代理——用便利換深度的一型。

把代理與自動補全區分開的是*驗證*。好的代理會讀自己的 diff、跑測試套件、持續迭代。你的工作從敲程式碼轉為**寫規約、做審查、守門禁**。

## 真正有效的學習路線

### 1. 命令列與 Git 熟練度（第 1 週）

代理活在終端裡。如果 `git diff`、`git log`、分支、rebase 還不是肌肉記憶，先補這個——所有代理式工作流都建立在審查 diff 之上。

### 2. 深學一個工具（第 2〜4 週）

選 Claude Code 或 Codex，把它學*透*：會話管理、記憶檔（什麼該進 CLAUDE.md、什麼不該）、權限模式、hooks、自訂命令。掃過教學你得到的只是一個聊天機器人；吃透設定面，它才會變成交付機器。

- 選 Claude Code：[Claude Code 從入門到專案實踐](/zh-tw/books/claude-code/)——從第一條命令講到 hooks、skills、子代理、沙盒與 MCP，最後以兩個真實專案收尾。
- 選 Codex：[Codex 從入門到專案實踐](/zh-tw/books/codex/)——從基礎到 OpenAI 工具鏈上的生產級專案。
- 想懂工具背後的心智模型：[圖解 AI Agent](/zh-tw/books/ai-agents/) 用視覺化講透規劃、工具呼叫與記憶架構。

### 3. 在真實程式碼庫上練（第 4〜8 週）

不是 todo 範例——是你真正在乎的程式碼庫。先給代理小而可驗證的任務（「幫這個端點加測試」），每個 diff 都審，審查能力跟得上才放大任務。最重要的紀律是：**解釋不了的 diff 絕不合併**。

### 4. 擴展工作流（第 8 週起）

2026 與 2024 的分野在這裡：規約驅動開發、代理必須通過的 CI 門禁、把團隊規範固化成自訂斜線命令、用子代理並行作業。上面兩本旗艦書的後半部整段都在講這件事——與代理一起交付*完整專案*，而不只是改檔案。

## 常見錯誤

- **Prompt 先行思維。** 代理會放大清晰的規約，救不了含糊的規約。
- **跳過審查門。** 正因為是代理寫的，你更得讀兩遍。
- **蒐集工具癖。** 淺學六個不如深學兩個。精通一個之後，模型無關的 [OpenCode](/zh-tw/books/opencode/) 是對沖。
- **沒有驗證迴圈。** 測試太弱，代理式編碼只會讓交付*更慢*，不會更快。

## 一句話總結

深學一個代理、讓人守住審查門、在真實倉庫上練、用規約與 CI 擴展。想要書本形式的完整路線，[AI 與智慧代理開發系列](/zh-tw/series/ai-agents/)會帶你從第一條命令走到交付的專案。
