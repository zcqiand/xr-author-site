AI 現在能寫出大部分程式碼——這正是*你*需要懂得更多、而不是更少的原因。這條路線圖帶你從零走到與 AI 代理一起交付真實專案，共四個階段。不變的鐵律：**AI 加速理解領域的人，擱淺不理解的人。**

## 階段一 — AI 替代不了的基礎（4〜8 週）

先學會讀程式碼，再學會生成它：

- **深入一門語言**——2026 年最穩的選擇是 Python 或 TypeScript。
- **Git 與終端**——commit、分支、diff、pull request。代理式工作流就是 diff 審查工作流。
- **Web 的運作方式**——HTTP、JSON、客戶端/伺服器的心智模型。

別因為「AI 會寫程式碼」就跳過這段。讀不了的東西審不了，審不了的程式碼就是團隊配送事故的方式。

## 階段二 — 認識你的第一個代理（2〜4 週）

裝一個代理式工具——Claude Code 或 OpenAI Codex——把它當*紀律*來學：

1. 會話與記憶：什麼該進 CLAUDE.md（或你的規約檔），以及為什麼上下文篩選才是真本事。
2. 只給小而可驗證的任務：「幫這個函式加測試」勝過「幫我做個 App」。
3. 每個 diff 都審。審查速度跟得上才放大任務。

- [Claude Code 從入門到專案實踐](/zh-tw/books/claude-code/)從安裝與第一個會話講起——不預設任何代理經驗。
- [Codex 從入門到專案實踐](/zh-tw/books/codex/)是 OpenAI 工具鏈上的平行路線。

## 階段三 — 做一個真實專案（8〜12 週）

選一條實戰路線，端到端完成真東西：

- **前端**：[React 從入門到專案實踐](/zh-tw/books/react/)（React 19 + TypeScript）——元件思維可遷移到所有現代 UI 框架。
- **後端**：[Spring Boot](/zh-tw/books/spring-boot/) 或 [Ruby on Rails](/zh-tw/books/ruby/)——伺服器端基礎、資料庫、部署。
- **資料**：[PostgreSQL DBA 實戰](/zh-tw/books/postgresql/)——AI 代理仰賴你驗證的資料建模與營運。

階段三的重點不在框架——在於以代理為結對，體驗一次完整交付週期：規約 → 實作 → 測試 → 部署。這個階段的每本書都以兩個完整真實專案為骨架，就是為了讓你把這個週期練兩遍。

## 階段四 — 規模化的代理工作流（持續）

手上有了一個交付過的專案後，升級*工作流*：

- [圖解 AI Agent](/zh-tw/books/ai-agents/)——引擎蓋下的架構：規劃、工具呼叫、記憶、多代理設計。
- CI 門禁、規約驅動開發、自訂 hooks 與命令——[Claude Code](/zh-tw/books/claude-code/) 與 [Codex](/zh-tw/books/codex/) 兩書的後半部整段都在講如何以這種方式交付完整專案。
