Claude Code（Anthropic）と OpenAI Codex は、2026 年においてどちらも成熟したエージェンティックコーディングツールです。そして両者とも同じ基本ループを回します：計画 → 編集 → 検証 → 繰り返し。違いは思想、拡張性、チームでの収まりどころにあります。実践的な比較をどうぞ。

## 結論を先に

- **先に Claude Code を学ぶべきなのは** — ターミナルで仕事をし、深いカスタマイズ（フック、スキル、サブエージェント、権限ポリシー）を求める場合。チームにきめ細かいサンドボックスと監査証跡が必要な場合もこちら。
- **先に Codex を学ぶべきなのは** — OpenAI エコシステム中心の仕事で、仕様をクラウド常駐エージェントに丸ごと渡すスタイルが合う場合。ChatGPT や OpenAI API との統合がプロダクトの要件になっている場合も。
- **いずれ両方学ぶ。** ループは同じです。ツール非依存のスキル — 仕様を書き、レビューし、ゲートする — は完全に転用できます。

## ワークフローの思想

**Claude Code** はターミナルネイティブです。セッションの中で暮らし、メモリは `CLAUDE.md` に蓄積され、カスタムスラッシュコマンド、スキル、出力スタイル、そしてツールイベントで走るフックで振る舞いを形づくります。サブエージェントが作業を並列化します。権限モデル（許可リスト、サンドボックスモード）はエンタープライズのゲート向けに設計されていて、見張り番なしでエージェントの触れる範囲を制約できます。

**Codex** は*仕様*をエージェントに渡して結果をレビューするスタイルを重んじます — 長時間の、仕様がきちんと書かれたタスクに強く、OpenAI の各サービス（CLI、IDE、クラウド）と統合されています。タスク定義がすでに文書化されている（Issue や仕様書がある）なら、Codex の流れは自然に感じられるはずです。

## 拡張性とコントロール

| 観点 | Claude Code | OpenAI Codex |
|---|---|---|
| カスタマイズ面 | フック、スキル、カスタムコマンド、出力スタイル | 仕様テンプレート、設定 |
| 並列化 | サブエージェント | クラウドタスクのファンアウト |
| アクセス制御 | 権限モード、サンドボックス、監査フック | ポリシー設定 |
| モデル結合 | Anthropic モデル | OpenAI モデル |

どちらも「一つのエージェント」を思想に外へスケールするモデルで、仕組みの違い以上に結果の違いはありません。

## どちらにどの本を

- [Claude Code 入門からプロジェクト実践へ](/ja/books/claude-code/) — Claude Code の設定面（セッション、メモリ、フック、スキル、サブエージェント、サンドボックス、MCP）を現時点で最も深く扱った一冊。エージェントとともにエンドツーエンドで納品した二つの実プロジェクト（RPG システムと財務システム）で締めます。
- [Codex 入門からプロジェクト実践へ](/ja/books/codex/) — OpenAI ツールチェーン版の同じプロジェクト駆動アプローチ：基礎、レビューループ、本番グレードのプロジェクト。
- 両者の背後にあるアーキテクチャの「なぜ」が知りたいなら、[図解 AI エージェント](/ja/books/ai-agents/) を先に。エージェントの計画、ツール呼び出し、メモリを視覚的に解説し、読めば両ツールが同じ言語の方言に見えてきます。

## まとめ

勝者がすべてを取る選択という枠は捨てましょう。チームの重心に合うツールを選び、カスタムフックと CI ゲートを自作できるまで学び込み、二つ目は週末に拾えばいい。*エージェンティックなエンジニアリングの規律*こそが長く使えるスキルで、上記の書籍はその両サイドを教えてくれます。
